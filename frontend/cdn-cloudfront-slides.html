09
02 시작하기 전 기본 개념

세 가지만 알면 됩니다

AWS S3
  • 파일을 통째로 넣고 꺼내 쓰는 오브젝트 스토리지
  • 폴더처럼 보이지만 실제로는 버킷 안에 키(경로) + 파일
  • 이미지, 번들, 빌드 산출물의 보관소
CloudFront
  • AWS가 운영하는 CDN
  • 전 세계 750개 이상의 엣지 로케이션
  • 있으면 Cache Hit로 바로 응답, 없으면 Miss로 S3에서 한 번 가져와 저장
OAC
  • S3를 Public으로 열지 않고 CloudFront만 접근하게 하는 방식
  • S3는 노출되면 안 되는 DB라고 생각하기
  • CloudFront가 유일한 Gateway

범용 vs 디렉터리 버킷

범용 버킷은 여러 가용영역(AZ)에 복제해 보관하고 모든 기능을 쓸 수 있는 기본 버킷.

디렉터리 버킷은 S3 Express One Zone 전용으로, 단일 AZ에 몰아넣어 지연시간을 줄이는 용도.

3️⃣ Bucket Policy

S3 직접 접근 ❌, 오직 CloudFront로만 ⭕ 

{
  "Sid": "AllowCloudFrontServicePrincipal",
  "Effect": "Allow",
  "Principal": { "Service": "cloudfront.amazonaws.com" },
  "Action": "s3:GetObject",
  "Resource": "arn:aws:s3:::scent-jo-images/*",
  "Condition": { "ArnLike": {
    "AWS:SourceArn":
      "arn:aws:cloudfront::<ACCOUNT_ID>:distribution/<DIST_ID>"
  }}
}
S3 객체 URL로 직접
bucket.s3.amazonaws.com/img.png
403
CloudFront 도메인으로
xxxx.cloudfront.net/img.png
200
🔒
OAC를 자동 설정하면서 Policy도 알아서 이 CloudFront로 잡아 줍니다. "S3는 노출되면 안 되는 DB"가 여기서 완성돼요.

4️⃣ 커스텀 도메인 · ACM

내 도메인을 붙이려면
인증서가 먼저 필요합니다

AWS Certificate Manager
  • AWS가 공인 SSL/TLS 인증서를 발급하고 만료 전 자동 갱신
  • CloudFront, ALB에 붙여 쓰는 인증서는 무료
  • xxxx.cloudfront.net은 이미 HTTPS. 하지만 cdn.scent-jo.dev를 붙이는 순간 그 도메인을 증명할 인증서가 따로 필요

‼️ 반드시 us-east-1 (버지니아 북부)

CloudFront는 리전으로 구분되지 않는 글로벌 서비스입니다. 그래서 CloudFront에 붙일 ACM 인증서는 무조건 us-east-1에서 만들어야 해요.

여러 서브도메인을 쓸 계획이면 *.scent-jo.dev 와일드카드로 발급해 두면 계속 재사용할 수 있습니다.

4️⃣ DNS 검증 두 갈래

도메인을 어디서 관리하느냐에 따라

Case 1 · AWS Route 53

버튼 한 번이면 끝

  • "Route 53에서 레코드 생성" 클릭 → 검증용 CNAME 자동 등록
  • CloudFront 연결도 CNAME 대신 A 레코드 + Alias
  • Alias는 scent-jo.dev 같은 apex 도메인에도 걸 수 있고 조회 요금 없음
  • 이미 외부 네임서버를 쓴다면 이사할 필요는 없음
Case 2 · Cloudflare, 가비아 등

CNAME을 직접 등록

  • ACM 생성: 도메인 이름 · 내보내기 비활성화 · DNS 검증
  • ACM이 주는 CNAME 값을 내 네임서버 DNS 레코드에 등록
  • 몇 분 뒤 "성공"이면 발급 완료
  • 계속 실패하면 CAA 레코드 두 줄 추가
